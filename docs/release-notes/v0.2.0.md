# AiiDA Flux Scheduler 0.2.0

Released 2026-11-06.

Version 0.2.0 adds explicit direct-versus-managed submission behavior and makes
named shared pools resilient to queued allocations, interrupted submissions,
and broker shutdown. It also includes fixes from follow-up review of allocation
ownership, resource validation, walltime handling, cancellation, and journal
maintenance.

Python 3.12 or later is required.

## Highlights

### Direct submissions and allocation lifecycle

Jobs now submit directly with `flux batch` by default; queue, account, and
walltime options alone do not create an allocation. To opt into managed
allocation behavior, set `flux_allocation_lifecycle` to `child` or `parent`.
Use `flux_pool` for a named shared allocation. See
[Basic Submission](../usage/basic-submission.md) and
[Scheduler Options](../reference/scheduler-options.md).

### Resilient pooled submissions

Pool allocation creation does not wait for queued resources while holding the
pool lock. Pooled jobs receive stable `allocation:pending-CalcJobUUID` IDs, and
the scheduler submits child jobs as the nested broker becomes ready. Durable
remote journals allow the scheduler to reconcile uncertain acceptance rather
than blindly resubmit. Cancellation targets a pending intent or its child, not
the shared pool allocation.

### Safer recovery and cleanup

Pool lock recovery requires proof that an aged owner is dead in the local
process context; age alone does not permit reclaiming foreign or unverifiable
locks. Manual journal cleanup checks sealed AiiDA CalcJobs and applies
fingerprint approvals in bounded batches. Automatic cleanup is best-effort and
retains allocation receipts and guard files.

## Behavior changes

- **Default submission path:** Existing workflows that depended on implicit
  allocation creation must opt into `flux_allocation_lifecycle="child"` or
  `"parent"`. Otherwise they submit directly with `flux batch`.
- **Remote requirements for pools:** Named pools require Linux remote
  execution, `flock`, and `flux python`. Verify that the site's Flux version
  and resource inventory support the requested options.
- **Upgrade procedure:** Stop old daemon workers before upgrading. Mixed old
  and new pool-lock protocols are unsupported. Preserve
  `$HOME/.aiida-flux-scheduler` journals and guards; deleting them can permit
  duplicate submissions or break lock serialization.
- **Operational validation:** Test queueing, recovery, and cancellation at the
  target site before production use. The project test suite does not replace
  live-cluster validation.
